# sylvenndt/apps

Personal phone apps (PWAs) for the owner, published via GitHub Pages at https://sylvenndt.github.io/Apps/ (branch `main`, root).

Conventions:
- Each app lives in its own folder (`<app-slug>/`) with its own `index.html`, `manifest.json` (start_url/scope `./`), icons and optional `sw.js`, so it can be added to the home screen on its own.
- Register every new app in the `APPS` array in the root `index.html` (path, name, desc, icon, color).
- UI text in Simplified Chinese; mobile-first; no build step — plain static files.
- Commit and push to `main`; Pages redeploys automatically in ~1 minute.
- linking-practice (每日美语): library sentences/words are pre-recorded Kokoro clips in `linking-practice/audio/` (see `tools/kokoro-audio/README.md`). After adding or changing sentences in data.js/vocab.js, regenerate clips there and bump `AUDIO_V` in neural.js; unrecorded text falls back to on-device Kokoro or the system voice.
- linking-practice: every dialogue line has an emotion (`emotion.js`; new scenes put it as the 4th item field "line/reply"). Clips are recorded with that emotion's prosody; changing an emotion means re-recording that clip and bumping `REV_TAG` in mkindex so phones refetch it. The SW keeps clips in a separate `fluent-audio-v1` cache that survives app updates.
- linking-practice: all "speak" features call `startListening` in `stt.js`, which first asks for mic permission (getUserMedia) and then uses either the browser's SpeechRecognition or its own recording + on-device Whisper (transformers.js from jsDelivr, model from Hugging Face with hf-mirror fallback). "auto" switches to Whisper after the system recognizer fails twice or on iPhone home-screen apps. Local results include the recording (`audio`, WAV) for playback. Default on-device model is distil-whisper/distil-small.en (q8, ~172MB).
- linking-practice: after speaking, `evaluateSpeech` in `pron.js` scores pronunciation with Azure Pronunciation Assessment (REST short-audio endpoint, Speech SDK from jsDelivr as fallback; key/region in settings, free F0 tier) and, for free-form answers, asks the AI for grammar/wording fixes.
- linking-practice: every LLM call (speaking coach, grammar fixes, connection test) goes through `AI.chat()` in `ai.js`, which uses DeepSeek (OpenAI-compatible `/chat/completions`, JSON mode, optional proxy base URL) or Claude, per the 「AI 批改」 setting.
- linking-practice (每日美语): its service worker is cache-first for versioned assets, so after changing any JS/CSS bump the `?v=N` query in `index.html`, `V`/`CACHE` in `sw.js` AND `APP_VERSION` in `core.js` together, or phones keep the old files. Open copies of the app then show a "新版本" banner (controllerchange) to reload. The SW also adds COOP/COEP headers so the Kokoro AI voice worker gets multithreaded WASM.
- qingmiao (轻描): a native Android app (Kotlin + OpenGL ES 3.0 + Compose), not a PWA, with **online updates**: the APK is only a shell (`qingmiao/android/app`: `MainActivity` + `Updater`) that bundles every library and AI model; all features/UI live in the `:core` library module (`qingmiao/android/core`, package `app.qingmiao.core`, entry `Entry.onCreate/onNewIntent` called by reflection). CI compiles `:core`, d8-dexes it into `core-N.jar` and publishes it to Pages at `qingmiao/update/` with `core.json` (version, sha256, minShell); the shell downloads the newest on every launch (jsDelivr fallback), verifies sha256, loads it with DexClassLoader, and falls back to the bundled copy after two crashes. So most changes ship by just pushing — the user never reinstalls. Rules: core must not use `R` (load assets via `context.assets`); adding a library, a model, a manifest permission or changing shell code needs a new shell — add the dependency to BOTH `app` and `core` build files, bump `Updater.SHELL_VERSION` and `min-shell.txt`, and send the user the new APK. The shell APK (with minify off) is the `qingmiao-latest` GitHub release; the user wants the APK file sent directly in chat, not a link. Signed with the committed sideload key `app/qingmiao-sideload.jks` (password qingmiao). Pull before pushing — the workflow pushes to main. Spec / prompt docs live in the user's 「轻描 Android 提示词总集」.
- qingmiao image pipeline (`core/.../gl/Pipeline.kt`, `gl/Shaders.kt`): skin work is frequency separation in sRGB-encoded YCbCr with fast-guided-filter coefficients computed once per image at ≤1024px and applied with the full-res guide, so preview and export share coefficients (WYSIWYG). Tone/WB in linear light. Hard caps live in `Uniforms.from()`. Skin/hair/person masks come from MediaPipe selfie_multiclass segmentation and eyes/mouth/lips/under-eye from the 478-point face landmarker (`Vision.kt`), uploaded as textures; the platform `android.media.FaceDetector` is only a fallback. `Enhancer.kt` (Real-ESRGAN general-x4v3 / x4plus) and `Inpainter.kt` (LaMa-Dilated eraser) run with LiteRT + GPU delegate and replace the working full-res bitmap. All model files are downloaded in CI (see the workflow), not committed. Shaders compile and run on desktop Mesa GLES (EGL surfaceless) — handy for testing without a phone.
