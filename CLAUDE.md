# sylvenndt/apps

Personal phone apps (PWAs) for the owner, published via GitHub Pages at https://sylvenndt.github.io/Apps/ (branch `main`, root).

Conventions:
- Each app lives in its own folder (`<app-slug>/`) with its own `index.html`, `manifest.json` (start_url/scope `./`), icons and optional `sw.js`, so it can be added to the home screen on its own.
- Register every new app in the `APPS` array in the root `index.html` (path, name, desc, icon, color).
- UI text in Simplified Chinese; mobile-first; no build step — plain static files.
- Commit and push to `main`; Pages redeploys automatically in ~1 minute.
- linking-practice (每日美语): library sentences/words are pre-recorded Kokoro clips in `linking-practice/audio/` (see `tools/kokoro-audio/README.md`). After adding or changing sentences in data.js/vocab.js, regenerate clips there and bump `AUDIO_V` in neural.js; unrecorded text falls back to on-device Kokoro or the system voice.
- linking-practice: every dialogue line has an emotion (`emotion.js`; new scenes put it as the 4th item field "line/reply"). Clips are recorded with that emotion's prosody; changing an emotion means re-recording that clip and bumping `REV_TAG` in mkindex so phones refetch it. The SW keeps clips in a separate `fluent-audio-v1` cache that survives app updates.
- linking-practice: all "speak" features call `startListening` in `stt.js`. In the Android app (`window.DSHASR` present) `Listener.engine()` is always `"native"`: record with the shell's AudioRecord (`DSHREC.start3` returns a boolean — the 2.x shell returned nothing, which made every tap say "麦克风打不开"), then recognize on-device with the bundled Parakeet model (`NativeAsr`, polls `DSHASR.job`). In browsers it asks for mic permission (getUserMedia) and uses either SpeechRecognition or its own recording + on-device Whisper (transformers.js, model from ModelScope/hf-mirror); "auto" switches to Whisper after the system recognizer fails. Results include the recording (`audio`, WAV) for playback. `normalize()` in linking.js spells digits/times/ordinals as words before comparing (Parakeet writes "6am", "22").
- linking-practice Android app (`linking-practice/android`, plain Java WebView shell, versionName 3.N): pages are served by `WebFiles` from the fixed origin `https://appassets.androidplatform.net/linking-practice/` (shouldInterceptRequest) — a fixed origin so localStorage/caches survive restarts (2.x used a random localhost port, so every launch was a fresh site: settings, progress and downloaded models were lost). Sources: newest downloaded web version in `files/web/vN/`, else the copy bundled in `assets/web/` (CI rsyncs the repo folder minus audio/, stt/, android/), else proxied from Pages. Online update: the shell reads Pages `sw.js` (`V` and the `CORE` list), downloads those files, checks index.html `?v=N` and core.js `APP_VERSION`, switches, and fires `dsh-update` (page shows the reload bar). So web changes ship without a new APK — just keep every file the page loads in `CORE`. No service worker in the app. Bridges: `DSHREC` (record/permission: permState granted|prompt|denied|blocked), `DSHASR` (sherpa-onnx 1.13.8 AAR + NVIDIA Parakeet TDT 0.6B v2 int8 in `assets/asr/`; the 650MB encoder is prepared once into `files/asr/` (marker `READY-<MODEL_ID>`; bump `MODEL_ID`/`ENC_SIZE`/`ENC_SHA256` when changing models) by `Asr.prepare`: the full APK carries it xz-compressed in 64MiB blocks (multi-threaded `Unxz`, state `unpacking:N`); the lite APK (~60MB, small enough to send in chat) downloads it once — first the xz from release `dailyenglish-model` (CI uploads it), then hf-mirror / Hugging Face raw — with Range resume and a SHA-256 check (states `download:pct:MBps:MB`, `verifying`; on metered networks it waits in `need-download` until the page calls `DSHASR.download()` after asking the user); preloaded after page load; ~0–3% WER on our clips), `DSHTTS`, `DSHAPP` (versions, updateNote, checkUpdate, copy, openUrl). Model + AAR are downloaded in CI, never committed. Workflow `dailyenglish-android.yml` (runs on changes under `linking-practice/android/`) builds a lite test APK with x86_64 (so the emulator exercises the model download), runs `android/ci/e2e.sh` on an emulator (drives the real WebView over DevTools: page origin, model load, recognition of real clips, recording, speak flow, data surviving restart), uploads the report + screenshots to the `dailyenglish-test` release, and only then publishes the arm64 lite + full APKs as release `dailyenglish-latest` and writes `download/apk.json`. Signed with the committed `app/dailyenglish-sideload.jks` (password dailyenglish); the 2.x key was lost, so going from 2.x to 3 needs one uninstall. The release has both `DailyEnglish.apk` (full, ~465MiB — over the ~400MiB chat-upload cap) and `DailyEnglish-lite.apk` (~60MB); the user wants the APK sent in chat, so send the lite one (download from the release, then SendUserFile).
- linking-practice: after speaking, `evaluateSpeech` in `pron.js` scores pronunciation via `Pron.assess`, per the `pronProvider` setting: default 讯飞 ISE 语音评测流式版 (`Xfyun`: WebSocket `wss://ise-api.xfyun.cn/v2/open-ise`, HMAC-SHA256 signed URL, en_vip read_sentence, 16k PCM frames; APPID/APISecret/APIKey in settings; 500 calls/day free) or Azure Pronunciation Assessment (REST short-audio endpoint, Speech SDK fallback). Both are normalized to the same `{total, acc, flu, comp, words[{w, acc, err, phon}]}` shape (`parseXfyun` converts 讯飞's 5-point XML ×20). For free-form answers it also asks the AI for grammar/wording fixes.
- linking-practice content: `extra.js` (after replies_zh.js, also in sw.js CORE) adds Chinese (`EX_ZH`) and a reply line (`EX_REPLY`) for every vocab/pattern example, so every card has `zh` and `reply`; `zhOf(text)` looks up any sentence's Chinese. Chinese is hidden until tapped (`zhTap()` in app.js, `.zh-tap`). New sentences must come with zh + reply.
- linking-practice randomness: `SESSION_SEED` + `seededShuffle(arr, salt)` in core.js give a new random order on every app open (stable within the session) — due reviews, new items (scenes/patterns/words), topic of the day, topic list/hints, link-page sentence. Use it for any new list instead of fixed order.
- linking-practice: every LLM call (speaking coach, grammar fixes, connection test) goes through `AI.chat()` in `ai.js`, which uses DeepSeek (OpenAI-compatible `/chat/completions`, JSON mode, optional proxy base URL) or Claude, per the 「AI 批改」 setting.
- linking-practice (每日美语, browser/PWA): its service worker is cache-first for versioned assets, so after changing any JS/CSS bump the `?v=N` query in `index.html`, `V`/`CACHE` in `sw.js` AND `APP_VERSION` in `core.js` together, or phones keep the old files. Open copies of the app then show a "新版本" banner (controllerchange) to reload. The SW also adds COOP/COEP headers so the Kokoro AI voice worker gets multithreaded WASM.
